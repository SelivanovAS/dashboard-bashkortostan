# СберСуд · Республика Башкортостан

Мониторинг гражданских дел ПАО Сбербанк: основная картотека и отдельный раздел
«Иски банка». Территория использует собственные данные, Worker/KV, ключи доступа
и браузерное хранилище.

- Первая инстанция: 45 районных, городских и межрайонных судов.
- Апелляция: Верховный Суд Республики Башкортостан.
- Кассация: Шестой кассационный суд общей юрисдикции.
- Все 23 судебных присутствия из исходного списка сопоставлены с серверами
  основных судов и учтены в реестре.

## Сбор и ручное пополнение

Начальный срез 11.09.2026: первые страницы 46 открытых источников, 63 дела основной
картотеки и 597 исков банка. Остальная история пополняется вручную через импорт.
Все 47 источников доступны владельцу и операторам.

Поиск Шестого КСОЮ требует проверочного кода: операторы загружают сохранённую
выдачу, после чего парсер проверяет известные карточки. Время заседания этого
суда — Самара, UTC+4; у судов Башкортостана — UTC+5.

Основной исполнитель — существующий VPS: регулярный запуск Башкортостана включён.
Ближайший плановый сбор — 14.09.2026 примерно с 06:20 по Екатеринбургу,
доставка — с 08:45. Пилот 12.09 завершился успешно: 672 дела и два сообщения
в прежний Telegram-чат. Mac подготовлен как ручной резерв; автоматический
список Mac новую территорию не содержит.
Публикация данных предшествует сборке дайджеста и рассылке через GitHub Actions.
Cron парсинга Worker выключен; обычный прогон и импорт используют общий lock своей копии.
С 15.09.2026 отдельный cron ежедневно в 02:17 Екатеринбург обслуживает профили:
7/30 дней без использования и 7 дней восстановления. Он не запускает парсинг
или рассылки. [Правила очистки](docs/technical/09-cloudflare-worker.md#очистка-неактивных-профилей-15092026)
и [проверенный выпуск](docs/Выпуск_очистки_профилей_2026-09-15.md).

## Разработка и сопровождение

Код Python выбирает `REGION=bashkortostan` из файла в корне. Фронтенд использует
`STORAGE_NS=bashkortostan`. `origin` — этот репозиторий, `upstream` — эталон
`SelivanovAS/dashboard`; push в upstream отключён в рабочих копиях.

При обновлении общего кода сохраняются региональные настройки, README и данные.
Новые файлы при merge проверяются отдельно: `merge=ours` их не защищает.
Для тестов нужны Python 3.12, зависимости `scripts/requirements.txt`, pytest и Node.
Команда: `python3 -m pytest`.
